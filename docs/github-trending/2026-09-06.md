**项目定位**

面向已被 Claude Code 生成的膨胀代码困扰、且具备代码评审能力的团队，通过注入 skill 使 Agent 在执行任务时优先最小 diff，从而降低 token 与复核成本。能力边界明确：它不参与需求分析和架构设计，也不支持未挂接 skill 的 Agent；基准来自单一 FastAPI 仓库，个人维护，需在安全敏感场景保持人工兜底。

**为什么值得关注**

今日新增 2845 星、star_today_ratio 2.22%，为 TOP3 最高，总星升至 12.79 万；提交虽由 1 天前暂缓为 2 天前，但 30 天 PR/issue 分别增至 127/46，open issues 达 219，社区贡献仍活跃。README 成熟，演示与文档齐全，遗憾 release 仍停在 v4.9.0，代码迭代滞后于热度，需观察是否吸引更多维护者。

**今天相比上次有什么变化**

**适合谁关注**

适合已建立单测与代码评审流程、希望降低生成代码冗余度及 Token 开支的 Claude Code 团队；喜欢把 YAGNI 写进 Agent 决策偏好的工程师也能快速受益。

**不适合谁关注**

不适合处理支付、医疗等必须显式防御的高风险逻辑；不适合让 Agent 免审直改或项目代码本已精简的场景；不使用 Claude Code 或无法安装 skill 的环境也无法落地。

**风险或争议点**

“100% safe”仅来自单一仓库 12 个任务，无法外推安全属性；过度抑制可能误删起防护作用的代码，故必须人工 review diff；项目由个人维护，v4.9.0 数月未更新，存在兼容性与长期支持风险。

**最佳实践场景**

选取一个刚交付且 diff 偏大的非关键 PR，让 Agent 在 ponytail 规则下重新 propose diff，并由两名 reviewer 对照功能测试与安全断言，统计 LOC、token 和评审时间的节省幅度。

**我会怎么试用它**

- 安装：在 Claude Code 插件市场安装 ponytail，或将其 rules/skill 文件放入项目；持续锁定当前 v4.9.0，避免未审计更新。
- 试跑：选定 1 个有完整单元测试和接口测试的非核心模块，运行 10 个左右的真实任务，收集生成 diff。
- 评估：对比无 ponytail 的基线：LOC 减少率、token/成本、测试通过率、人审发现的逻辑缺失数。
- 退出：若测试通过率显著下降、安全防线被删或评审节省不足 20%，则卸载并回归基线。
