## 1. mattpocock/skills

**项目定位**

面向真实工程场景的 Agent Skills 集合。项目把需求澄清、PRD、Issue 拆分、TDD、调试、架构改进、Git guardrail 等高频动作拆成小而可组合的技能，目标是让不同 AI 编码工具都能复用同一套工程流程。

**为什么值得关注**

它连续三天榜首，说明开发者正在把 AI 编码从“写一段提示词”升级为“维护一套可执行的工程方法”。这类项目的长期价值不只是技能数量，而是把需求对齐、反馈循环、架构复盘和提交安全这些容易被忽略的流程固定下来，减少不同成员、不同工具之间的执行偏差。

**最佳实践场景**

研发团队可以把它作为内部 Agent 工作流的种子库：先挑选需求澄清、TDD、调试、Git 防护这几类高频技能，改写成本团队术语和质量门禁，再纳入日常开发、评审和故障排查流程。这样比让每个人各自维护提示词更容易审计、复盘和迭代。

## 2. Alishahryar1/free-claude-code

**项目定位**

Claude Code 的 Anthropic API 兼容代理。它在本地暴露 Claude Code 期望的接口，再把请求路由到 NVIDIA NIM、OpenRouter、DeepSeek、LM Studio、llama.cpp、Ollama 等云端或本地模型后端，并处理流式响应、工具调用、模型路由、限流和超时配置。

**为什么值得关注**

它连续三天 TOP3，说明开发者对“保留熟悉的 Claude Code 入口，同时切换模型供应”的需求很强。项目的热度来自两个方向：一是成本和额度控制，二是给本地模型、云端模型、多模型分层路由提供统一实验入口。与此同时，这类代理会经过提示词、代码上下文和工具参数，安全边界必须比普通 CLI 插件更谨慎。

**最佳实践场景**

个人或小团队可以用它搭建受控的模型路由实验环境：轻量文档、代码解释、简单重构走本地 Ollama 或 LM Studio，复杂设计和高风险修改走更强的云端模型，并记录延迟、失败率、工具调用正确率和人工返工成本。正式接入生产代码前，应关闭原始请求日志，审查密钥处理方式，并确认所用模型服务条款允许对应用途。

## 3. abhigyanpatwari/GitNexus

**项目定位**

代码库知识图谱与 Agent 上下文引擎。它可以把代码库索引成包含依赖、调用链、模块聚类和执行流的知识图谱，再通过 CLI、MCP 或 Web UI 暴露给 Cursor、Claude Code、Codex 等 AI 编码工具使用。

**为什么值得关注**

AI 编码常见失败点不是“不会写代码”，而是看漏依赖、误判调用链、不了解模块边界。GitNexus 的热度说明开发者正在为 Agent 补齐结构化代码上下文，而不是只把更多文件塞进提示窗口。它同时提供本地 CLI + MCP 和浏览器 Web UI 两种路径，也让隐私、规模和快速探索之间有更明确的选择。

**最佳实践场景**

适合用于大型或陌生代码库的入门、重构前评估和 PR 影响面分析：先让 GitNexus 建立本地索引，再让 Agent 基于调用链、依赖关系和模块聚类回答“改这个接口会影响哪里”“这个流程真正入口在哪”“哪些测试最该补”。它不应替代测试和代码评审，但可以显著降低 Agent 盲改跨模块代码的概率。
