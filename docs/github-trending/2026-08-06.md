**项目定位**

面向多 Agent 协作团队和一人公司开发者，解决会话上下文丢失、文档/代码冷启动重复劳动问题，把对话、文档、代码沉淀为 Chat Memory、Skill、LLM-Wiki、Code-Graph 四类资产，并通过 Memory Hub 统一治理和跨框架分发。能力边界：依赖 OpenClaw/Hermes 等生态，需自行部署 memory-core/hub/proxy 三服务，不提供托管 SaaS；数据迁移 v2→v3 需额外工具，效果与团队使用规范强相关。

**为什么值得关注**

今日新增1892星，star_today_ratio 12.59%，总星数突破1.5万，属快速破圈；1天前有提交，v2.0.0（2026-08-03）刚发布，近30天PR更新528、issue更新96，说明社区反馈和迭代频率高；README 成熟（15K字符、26个标题、含安装/Demo/文档），并带中文文档和迁移工具，适合直接上手。

**适合谁关注**

适合多 Agent 系统或一人公司团队，希望让经验跨会话沉淀、新人快速加载团队记忆的开发者；适合已在用 OpenClaw、Claude Code 等代理工具、愿意自托管记忆服务的组织；适合需要统一管理对话、技能、文档、代码知识的企业知识工程团队。

**不适合谁关注**

不适合只想要轻量单会话记忆插件、不愿维护多服务的个人；不适合对数据隐私要求极高且不允许本地部署敏感数据的场景；不适合依赖官方托管、不想处理迁移或版本兼容的团队；对 OpenClaw/Hermes 生态无依赖的项目也不适用。

**风险或争议点**

项目仍处于 Team Memory Beta 阶段，open issues 518 较高；需自托管三服务，部署与运维成本不小；与特定 Agent 框架（OpenClaw、Hermes）紧密集成，生态变动可能带来兼容问题；记忆资产自动抽取涉及对话、代码、文档等内容，团队需设置治理与审查机制，避免敏感信息被共享或污染；v2→v3 迁移需谨慎备份。

**最佳实践场景**

在一个 3-5 人的 Agent 团队中，先用它导入现有文档库和代码仓库生成 LLM-Wiki 与 Code-Graph，再让新成员接手任务时直接加载团队记忆，减少重复解释；每次会话结束自动抽取 Skill 并经人审后入库，形成可持续复用的团队资产。

- 评估：分类准确率≥95%；文本型单文档处理<200ms；扫描件识别召回率≥98%；输出 Markdown 可读性达到内部文档规范；内存占用低于现有方案。
- 退出：若准确率不达标、API 变动影响集成或复杂版式失真严重，则回退 PyMuPDF + OCR 路由；若达标则嵌入主处理管道并加沙箱与回归用例。
