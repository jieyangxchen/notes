**项目定位**

面向要给代理加“桌面操作能力”的自动化开发者：通过 macOS/Windows/Linux 无障碍树快照出可操作 ref，代理按 ref 执行并重新快照校验，避免像素匹配。边界是只覆盖无障碍树暴露的元素，画布、游戏、自绘 UI 等无节点界面不可用；headless 默认不抢焦点。

**为什么值得关注**

单日 +2275 星、占比 23.76%，是本周最陡的新项目爆发；1 天前有提交，v1.0.2（10-30）已发布，README 6,932 字符含安装、Demo、文档，给出 60 个命令名、JSON 错误码与 retry 语义。30 天 PR 203 对 122 个 open issue，维护比多数新项目跟得上；ref 过期与 PowerShell 引号是常见踩坑点。

**今天相比上次有什么变化**

今日新进 TOP3，暂无昨日同榜对比

**适合谁关注**

适合需要让代理操作内部桌面软件（ERP 客户端、旧版后台）的自动化团队，以及想用 CLI 给自家 agent 加桌面动作、并愿意处理无障碍授权与 ref 失效重试的工程师；macOS 需辅助功能权限，Linux 需 at-spi2-core 图形会话。

**不适合谁关注**

不适合目标应用是画布、游戏或自绘 UI、无障碍树无节点的场景；也不适合会把桌面截图、剪贴板内容随手写进公共日志的团队；对需要物理鼠标轨迹的测试，或终端权限低于目标应用的 Windows 进程，同样不适用。

**风险或争议点**

快照、剪贴板、截图与命令输出都可能带出私人桌面内容，README 明确要求不要进公共日志与上传；可选 JEV helper 会把屏幕描述发给模型提供方，属独立组件。桌面自动化等于把键鼠权限交给代理，须设应用白名单与人工复核，金融、医疗等敏感终端不建议直连。

**最佳实践场景**

在隔离测试账号里让代理操作一个内部工单客户端：先用 snapshot --skeleton 摸清结构，再按 ref 填表提交，最后重新快照核对结果，所有输出落到本地临时目录而非日志系统。

**我会怎么试用它**

- 安装：在测试机用 npm 安装，macOS 先跑 agent-desktop permissions --guide 授予辅助功能权限，Linux 确认 at-spi2-core 与图形会话存在，记录版本与卸载方式。
- 试跑：选一个非敏感桌面应用，写一个“观察—操作某 ref—再观察”的最小脚本，连续跑一周只做查询与填表类低风险动作。
- 评估：统计单任务成功步数、STALE_REF/AMBIGUOUS_TARGET 出现频率、重试是否收敛，以及快照与截图中是否出现不该外传的内容。
- 退出：若出现无法限定应用范围、频繁 STALE_REF 导致误操作，或快照被迫进入公共日志，即停用并撤销辅助功能授权、清理临时输出目录。
