**适合谁关注**

适合需快速摸清上万行多语言仓库结构、追踪依赖与调用链的开发者与架构师；也适合想把代码、SQL schema 与设计文档串联起来做调研的研究者，且能接受本地 AST 解析后人工抽检结果。

**不适合谁关注**

不适合代码量极小、逻辑简单、图谱收益覆盖不了生成成本的项目；不适合必须实时反映最新改动的在线系统；对代码外发零容忍的团队须禁用文档、PDF、图片的语义增强通道，否则内容会离开本机。

**风险或争议点**

**最佳实践场景**

对一个多微服务仓库运行 /graphify 生成 graph.json，用 query 定位鉴权相关模块、用 path 追踪一条请求的完整调用链，与手工梳理结果对照后再用于重构评审，而非直接依据图谱结论改动代码。

**我会怎么试用它**

- 安装：在 Claude Code 或 Cursor 中按 README 安装 /graphify 技能，先关闭需要外部 API 的文档语义通道。

- 评估：用 10 个真实问题核对答案相关性、误关联边数与路径完整度，对比手工 grep 与查阅文档的耗时。
- 退出：若连续三个仓库查询准确率不及手工检索，或修正图谱耗时超过收益，则停用并回退为 grep 加文档。
