**项目定位**

面向软件开发者与研究者，通过 AST 解析和可选语义增强，将代码、文档、数据库 schema 等整合为结构化图，支持查询、路径追踪和解释；强调本地优先，无 LLM 参与代码解析，保护隐私。

**为什么值得关注**

日增 1095 星，star 占比 1.29%，老项目回热；v0.9.15 刚发布，提交活跃；近 30 天 issue/PR 分别 281/345，社区参与度高；跨 15+ 编程助手平台，基准测试召回率突出，尤其 LOCOMO 与 LongMemEval 表现亮眼。

**今天相比上次有什么变化**

今日新进 TOP3，暂无昨日同榜对比

**适合谁关注**

需要理解大型代码库结构、追踪依赖关系的开发者与架构师；希望建立代码与文档、论文之间关联的研究者；使用 AI 编程助手，需增强上下文检索的团队。

**不适合谁关注**

项目代码量极小或逻辑过于简单，不足以从图谱中获益的情况；必须实时动态分析的在线系统；对代码隐私极度敏感，无法接受任何外部 API 调用的环境。

**风险或争议点**

代码解析完全基于 AST，可能遗漏动态特性或宏展开；语义增强部分若使用第三方模型，存在代码泄露风险；图谱准确性依赖于解析器覆盖度，部分语言可能不完整；结果需人工校验。

**最佳实践场景**

对一个拥有多个 microservice 的项目运行 `/graphify`，生成 graph.json，使用 `graphify query` 查询特定模块的所有依赖，或 `graphify path` 追踪一个请求的完整调用链，辅助理解与重构决策。

**我会怎么试用它**

- 安装：在 VS Code 或兼容的 AI 编程助手中安装 Graphify 插件，或通过 CLI 安装。
- 试跑：选择一个 1 万行以上的 Python 或 TypeScript 项目，运行 /graphify 生成图谱文件，执行 query "how does authentication work?" 并验证结果。
- 评估：评估查询结果的相关性与精确度，记录误关联数量；检查路径追踪是否完整，对比手动梳理所需时间。
- 退出：若连续 3 个项目查询结果不可信，或花费在修正图谱上的时间超过手动查找，则暂停使用；考虑向项目提交 issue 报告语言解析不足。
