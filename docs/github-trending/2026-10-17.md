**不适合谁关注**

数据量很小、用编辑器全局搜索即可满足的个人项目；要求 GA 稳定版与长期兼容承诺的生产系统；对检索质量与权限隔离有强合规要求、无法接受 rc 版本变动的金融或政务场景。

**最佳实践场景**

在受控目录先索引一两个私有仓库，让编码 agent 通过 MCP 检索历史实现与内部文档，对比同一任务在“agent 直接读文件”与“走 XERJ 检索”下的 token 消耗与一次通过率，用数据决定是否推广。

**我会怎么试用它**

- 安装：用官方一行安装脚本或单静态二进制部署（无需 JVM），先在本机对一个小仓库跑 autoindex，确认索引目录与 embedder 默认走离线词法模式。
- 试跑：选 1 个编码任务，让 agent 分别用 grep/直接读文件与 XERJ 检索完成，对比 token 数、耗时与修改正确率；再索引一份内部文档或 PDF 做问答测试。
- 评估：以 token 节省比例、任务一次通过率、检索召回与相关性、索引构建时间与磁盘占用为主要指标，并用自有数据复现“40 倍/2.7 倍”说法。
- 退出：若自测 token 节省不足 2 倍、检索召回明显不足、rc 升级频繁破坏索引，或将敏感数据索引后无法满足权限隔离，则退出试点并回退普通搜索。
