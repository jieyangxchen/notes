**项目定位**

面向用 AI coding agent 批量生产短视频的开发者或团队，解决从创意到 HTML/CSS/动画再到 MP4 的重复劳动。支持通过 skills 供 Claude Code/Cursor/Codex 调用，也可本地 CLI 使用。边界：适用于确定性渲染，不解决创意编排；需 Node/ffmpeg；商业 hosted 服务与开源版能力有区分。

**为什么值得关注**

今日新增 2627 星、star_today_ratio 5.5%，显著领跑同榜；总星 47,735，呈稳定升温。1 天前有提交，v0.8.32 刚发布；近 30 天 PR 更新 734、issue 更新 103，open issues 仅 87，社区反馈消化快。README 非常成熟，含 skills/demo/docs，适合作为 Agent 视频生成的可靠外部工具评估。

**今天相比上次有什么变化**

今日新进 TOP3，暂无昨日同榜对比

**适合谁关注**

适合已在 Claude Code/Cursor 等 agent 工作流中需要视频输出、教程/营销封面自动生成的内容技术团队；也适合想复用 HTML/GSAP 技能做动态视觉、又希望产出可审计 MP4 的开发者。可先用本地 CLI 试点。

**不适合谁关注**

不适合追求影视特效、非线性剪辑或复杂音画同步的用户；也不适合缺少 Node/ffmpeg 环境和 agent 配置经验的团队；若需要云端多人协作，先确认 HeyGen 托管服务条款，不要把本地 renders 直接当生产交付。

**风险或争议点**

渲染 HTML/媒体本质上是在本机执行不可信代码，必须放在隔离沙箱中；GSAP/ffmpeg 的参数注入可能导致资源耗尽或 RCE。Agent 自动调用 skills 时需检查 hook 权限和物料来源版权。HeyGen 为商业公司，开源版与 Pro/私有化版本边界潜在差异需自行核实。

**最佳实践场景**

选一个真实营销短视频需求，让 agent 在隔离目录中用 /hyperframes 完成分镜、编写 HTML、动画编排并渲染 MP4；邀请 2 名人工验收文案/节奏后入库。每次保留渲染用 HTML、资源和 prompt 到版本库，使内容可复现、可追责。

**我会怎么试用它**

- 安装：在 Node 18+ 环境运行 npx hyperframes skills update 或 npx skills add heygen-com/hyperframes --all；执行 npx hyperframes init 初始化；确认 ffmpeg 可用。
- 试跑：取 1 个真实需求（如 10 秒产品片头），让 agent 用 /hyperframes 生成至少 2 个 HTML 版本并渲染 MP4，记录 token 消耗。
- 评估：指标：渲染成功率、视频与 prompt 一致性、错误画面数量、从开始到交付耗时；并由 2 名成员人工评分。
- 退出：若连续 3 次渲染失败率高于 20%，或 agent 自动修改了无关文件的 hook 异常，则暂停并改回人工视频流程。

**项目定位**

**适合谁关注**

**不适合谁关注**

不适合需要高保真排版还原的出版、设计行业；不适合把不可信或超大文件直接交给未限制权限进程的团队；OCR 与音频转写依赖第三方能力，不适合离线或被屏蔽环境。注意 Excel 多 sheet、公式和图表解析有限。

**最佳实践场景**

用容器封装 MarkItDown 作内部文档网关：上传文件后先在沙箱转换，输出 Markdown 与源文件哈希，再送给 RAG；每天对合同类样本做金额、日期、单元格一致性抽检，偏差率超阈值就告警。

**我会怎么试用它**

- 安装：pip install "markitdown[all]"，要求 Python 3.10+；也可用 Docker 运行，避免污染开发环境。
- 试跑：选取 20 份不同格式样本（PDF/Word/Excel/PPT/图片），批量转 Markdown 后由人工抽查 5 份的关键字段。
- 评估：比较转换耗时、失败率、抽样准确率（金额/日期/表格单元格），并衡量转换后文档在向量库的检索命中率。
- 退出：若关键字段错误率高于 2%，或无法满足沙箱/权限合规要求，则不将其作为唯一转换链路并回退人工流程。
